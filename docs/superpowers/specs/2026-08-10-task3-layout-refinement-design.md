# Task 3 品牌布局视觉调整设计

## 目标

在不改变盛博润现有品牌识别和网站信息架构的前提下，重新整理 Logo 资产，并调整全站 Header、横向边距和 Footer。最终页面应在大屏上减少无效留白，在滚动时保留顶部导航，同时让 Footer 的层级、间距和配色接近用户提供的华为 Footer 参考图。

本设计是 Task 3 的视觉调整，不提前实现 Task 4 的产品中心页面，也不涉及部署、正式域名、DNS、HTTPS 或服务器操作。

## 已批准方向

采用“高保真 Logo 重制 + 华为式轻灰 Footer + 全宽受控边距”方案。

以下内容属于不可变约束：

- SBR 图形轮廓保持可识别，不重新设计商标。
- 三个青绿色节点及其连接关系保持不变。
- 公司名必须准确显示为“盛博润”，不得改字、漏字或使用近似字符。
- 顶部导航仍只有：首页、产品中心、解决方案、技术支持、关于我们。
- Logo 仍不是返回首页的链接。
- Footer 仍不显示电话、邮箱、地址或工作时间。
- 网站只在本地开发和测试，不访问或测试正式域名，不部署。

## Logo 资产

### 素材角色

- 当前 `public/brand/logo.png` 是品牌内容来源，决定 SBR 图形、青绿色节点和“盛博润”字样。
- 用户提供的华为 Logo 截图只用于参考图形与文字的相对大小、视觉重心和四周留白，不复制其造型、字体或颜色。

### 输出规则

- 最终文件继续使用 `public/brand/logo.png`，替换现有文件。
- 输出为 `1200 × 336` 横向透明 PNG，避免在白色 Header 上产生可见底框。
- 图像画布中的主体包围盒必须水平、垂直居中：左、右留白等长，上、下留白等长。
- 图形与文字的视觉中心位于同一水平线上。左侧 SBR 图形可以略高于文字，比例参考华为横向 Logo，但不得显得压过公司名。
- SBR 图形和“盛博润”的深色部分统一改为 `#1D1D1F`，与顶部导航“首页”的文字颜色一致。
- 青绿色节点保留品牌色 `#00B7B5`。
- 不增加渐变、阴影、描边、口号、水印或其他装饰。
- 最终验收必须检查中文文字准确性、图形完整性、透明边缘、等量留白和小尺寸清晰度。若生成式处理改变了商标或文字，应放弃该结果，不得以近似图形交付。

### Header 中的显示

- Logo 的显示宽度在桌面端固定为 144px，在移动端固定为 120px，不再依靠图像内部不均匀留白修正位置。
- Logo 文字部分的视觉中心必须与右侧导航文字中心对齐。
- 桌面和移动端分别设置稳定的显示尺寸，避免使用会在相邻断点突然放大的规则。

## 全站横向边距

当前 `75rem` 内容宽度上限会让超宽屏两侧产生过长空白。调整后：

- `.site-container` 使用完整可用宽度，不再以固定的 1200px 内容宽度限制 Header 和 Footer。
- 左右边距始终对称。
- 页面边距使用响应式规则 `clamp(1rem, 6.25vw, 7.5rem)`。
- 320px 宽度时每侧至少保留 16px；超宽屏时每侧最多约 120px。
- 将来正文需要限制阅读行长时，由具体正文组件设置局部最大宽度，不重新收窄全站容器。

## Header

### 尺寸和定位

- 桌面 Header 高度从 76px 缩小到 54px，减少约 29%。
- 移动端 Header 高度从 68px 缩小到 48px，减少约 29%。
- Header 使用 `position: sticky; top: 0` 固定在可视区域顶部，并保留足够的层级使正文不会覆盖导航。
- 粘性定位不额外挤压正文，也不引入页面横向滚动。

### 视觉和交互

- 背景保持接近不透明的白色，继续使用当前弱分隔阴影。
- 桌面导航顺序、文字、当前页状态和键盘焦点行为保持不变。
- 移动菜单继续使用现有按钮和 Escape 关闭逻辑；下拉菜单紧贴缩短后的 Header 底部。
- 所有可点击目标仍满足至少约 44px 的可操作高度，Header 视觉变矮不能牺牲键盘和触摸操作。

## Footer

### 信息结构

Footer 从上到下分为四层：

1. 动态 breadcrumb。
2. 第一条分隔线。
3. 五栏 Footer 导航。
4. 第二条分隔线和单行版权备案信息。

不增加搜索框、华为商城式额外链接行、社交媒体图标或最下方的联系我们／法律声明等附加链接。

### Breadcrumb

- Breadcrumb 位于 Footer 左上角，与第一栏标题的左边缘对齐。
- 首页显示“首页”。
- 未来内页显示“首页 / 当前页面”；多级页面可继续按传入顺序显示中间层级。
- `BaseLayout` 负责把页面 breadcrumb 数据传给 `Footer`。
- Breadcrumb 只在 Footer 中呈现，避免同一页面重复显示两组 breadcrumb。
- Breadcrumb 与导航之间设置一条 `#E8E8ED` 分隔线，并保留接近参考图的上下间距。

### 配色

- Footer 背景：`#F5F5F7`。
- 五栏标题：纯黑色 `#000000`。
- 子链接和 breadcrumb：`#6E6E73`。
- 两条横向分隔线：`#E8E8ED`。
- 悬停和键盘焦点继续使用站点品牌色规则，同时保持 WCAG 2.1 AA 文字对比度。

### 导航和响应式行为

- 桌面继续显示五栏：产品中心、解决方案、技术支持、关于我们、法律信息。
- Footer 的左、右边缘统一使用同一个 `.site-container`，消除视觉不对称。
- 移动端继续使用原生 `<details>` 折叠栏目。
- 移动端分隔线同步改为浅灰体系，并保留清晰的展开状态和键盘操作。

### 底部版权信息

删除当前左下角“盛博润”和右下角版权文字，替换为一条完整文本：

`版权所有 © 2011-2026 北京盛博润通信设备有限公司 ICP备案（待确认） 公安联网备案（待确认）`

桌面端按照参考图居中显示；空间不足时自然换行，移动端保持可读，不拆成互相竞争的左右两栏。

## 组件和数据流

- `BaseLayout.astro` 继续接收现有 `breadcrumbs` 属性，并将其标准化后传给 `Footer.astro`。
- 当页面没有显式提供 breadcrumb 时，`BaseLayout` 为首页提供“首页”默认项。
- `Breadcrumbs.astro` 继续负责语义化 `<nav>`、有序列表、链接和 `/` 分隔符，并增加适合 Footer 的样式入口。
- `Footer.astro` 负责 Footer 的四层结构和已有内容集合导航，不复制 breadcrumb 生成逻辑。
- `Header.astro` 只负责粘性定位、尺寸、Logo 和导航交互。
- `tokens.css` 定义页面边距和 Footer 可复用颜色；`global.css` 只处理全站容器规则。

## 测试先行与验收

实现前先扩展 `tests/e2e/layout.spec.ts`，让测试因旧布局而失败。至少覆盖：

- Header 的计算定位为 `sticky`、`top: 0`；页面滚动后 Header 仍位于视口顶部。
- 桌面 Header 高度约 54px，移动端约 48px，同时菜单仍可通过键盘打开和关闭。
- Logo 在桌面和移动端保持预期尺寸，Logo 文字视觉中心与“首页”导航文字中心对齐。
- 1440px、1920px 和更宽视口下，Header 与 Footer 的左右边距对称，且每侧不超过约 120px。
- Footer 背景、标题、链接、breadcrumb 和分隔线使用批准色值。
- 首页 Footer breadcrumb 显示“首页”；带 breadcrumb 的测试页面能显示动态路径。
- Footer 版权备案文字完全一致，并且不存在搜索框、社交图标和额外底部链接行。
- 320px、768px、1440px 和超宽屏均无水平滚动。

Logo 文件还需进行视觉检查：

- 与当前 Logo 对照，确认商标和文字没有变形。
- 与华为参考图对照，确认图形与文字比例更协调。
- 在透明背景和白色 Header 上检查边缘。
- 检查主体包围盒的上下、左右留白分别等长。

完整验证顺序为：布局端到端测试、单元测试、内容校验、Astro 检查、静态构建、全量 Playwright 测试，以及本地截图复核。所有浏览器测试只访问 `http://127.0.0.1:4321`。
